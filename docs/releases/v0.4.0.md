# Titan v0.4.0

This milestone aligns the engine workspace's eight Cargo packages with the
`v0.4.0` source tag. Earlier tags marked source milestones while Cargo packages
stayed at `0.1.0`. The standalone arena and starter retain their independent
`0.1.0` package versions. Packages remain unpublished (`publish = false`); use
the Git tag or an exact revision as the dependency source.

Since v0.3.0:

- Game-owned, bounded arena saves restore RNG, enemy state and dash/contact
  cooldowns without rewinding host time.
- The public `titan::replay` module provides bounded snapshot recordings,
  consumed digital input encoding and playback progression. Both games adopt it;
  snapshot schemas, simulation and validation remain game-owned.
- RPG snapshots recreate collected shards, restore shrine state and rebuild UI.
- Native and browser players support imported replay, pause, single-step,
  restart, input isolation and verified completion. Headless verification matches
  full game state and exact software pixels.
- CLI argument files and diagnostics preserve bounded input and session policy.

Arena v1/v2 recordings remain readable; RPG uses snapshot-backed v2 recordings.
Protocol and save/recording format versions are unchanged by the Cargo bump.
This is an early-development release, not a promise of stable APIs or formats.
Scrubbing, playback speed, broader UI layout/focus, and a general ECS serializer
remain outside this milestone.

The implementation passed native, WebAssembly and macOS CI at `c2566f6` in
[run 33951497780](https://github.com/titan-engine/titan/actions/runs/33951497780).
The release procedure tags the version-bump commit only after its own CI passes.
See [shared replay](../replay.md), [RPG controls](../rpg-replay.md),
[arena controls](../arena-replay.md) and [local evidence](../replay/local-checks.json).
